# Feature Specification: Task-agnostic action taxonomy & contract naming (close the Principle III gap)

**Repository**: secure-agent-kernel (Repo A, package `sr_agent`)

**Feature Branch**: `001-task-agnostic-contract`

**Paired feature**: araratsec-agent `002-pack-owns-action-taxonomy` (the downstream migration that consumes this contract). Neither ships alone — see **Cross-Repository Coordination**.

**Created**: 2026-08-09

**Status**: Implemented and merged (PR-1 `e217521` #2 · PR-3 shim removal `1f2373d` #3)

**Input**: User description: "The kernel package (`sr_agent`) is meant to be the task-agnostic, memory-injection-resistant core, but it still hardcodes smart-contract-audit vocabulary that Constitution Principle III assigns to a capability pack: the concrete `ActionType` enum (`run_slither`, `run_mythril`, `run_auditor_skill`, `write_poc`, `deploy_test_contract`, …), the domain privileged-status set (`audit_complete`), audit tools (`TOOL_REGISTRY`), per-action validation (`_validate_params`), plus audit-flavored names (`audit_root`, `AuditResult`, `PackContext.poc_dir`/`poc_generator`) and an audit default system prompt. Make the kernel's action taxonomy open, move the domain metadata out to the pack through the existing `CapabilityPack` surface, rename the residual audit vocabulary to task-agnostic names, and pin the result with a new boundary test — without weakening any kernel guarantee."

## Why this exists (the Principle III gap)

Constitution **Principle III (Kernel / Capability-Pack Separation)** states, verbatim, that "Task-specific capability — audit tools, **concrete action types**, planner stages, finding models, **domain privileged-statuses** — lives in a capability pack." The code violates this today:

- `sr_agent/models/action.py` defines `ActionType`, a **closed** enum of audit tool ids, and `Action.action_type: ActionType` (line 85) pins every action to that closed set.
- `sr_agent/models/memory.py:34` hardcodes `REQUIRES_HUMAN_CONFIRMATION = {"verified_safe", "skip_analysis", "audit_complete"}` — domain privileged-statuses, duplicated by the pack's own `AUDIT_PRIVILEGED_STATUSES`.
- `sr_agent/tools/registry.py` (`TOOL_REGISTRY`) enumerates audit tools; `sr_agent/orchestrator/action.py` (`_validate_params`) hardcodes per-audit-action parameter checks.

This is already recognized in the codebase: `audit_agent/pack.py`'s module docstring calls moving this metadata into the pack "a deferred, boundary-clean follow-up (needs a generic `Action.action_type`)." This feature **is** that follow-up. It is corrective, not additive: it closes a known gap between the code and the constitution the project already ratified.

The existing boundary suite (B1–B5, `tests/architecture/test_kernel_pack_boundary.py`) checks imports, config fields, routing slots, an arbitrary role map, and the test tree — but **not** the contents of the `ActionType` enum or the privileged-status set. So today's violation passes CI. This feature adds the missing guard.

### The three categories of action id (this is the crux — resolved up front)

The naive framing "kernel owns `ActionClass`, pack owns every concrete id" is **wrong**, and getting it wrong would break the very thing this feature exists to fix. There are **three** categories, not two:

1. **`ActionClass`** (`read_only`/`write_execute`/`memory`/`control`) — the generic risk taxonomy. Kernel-owned. Unchanged. It is the confirmation lever.
2. **Kernel-owned generic ids** — mechanisms and generic capabilities the kernel provides to **every** pack, independent of the domain. Partitioned by **validation behavior** (not by narrative role) — and B6 asserts on each partition separately:
   - **`KERNEL_GENERIC_ACTIONS` = `{write_memory, request_human_confirmation, read_file, search_code}`** — *resolvable* ids that flow through `validate_action` and therefore **have kernel-provided `ActionSpec`s**. Two sub-roles share this behavior and so share the set: the control/memory machinery the kernel's own loop constructs (`write_memory`, `request_human_confirmation`) **and** the generic scope-bounded reads (`read_file`, `search_code`) whose path-containment guard (`_contained`/`_check_filepath`) is a kernel safety primitive — decision **D6**. Both sub-roles are generic, not domain, so both stay kernel-owned; a second pack inherits file reading for free instead of re-declaring it (and re-rolling its own path-traversal check).
   - **`LOOP_TERMINALS` = `{escalate, complete}`** — loop *signals*, intercepted **before** validation (`loop.py:180`/`:189` batch, `:341` chat) and never reaching `validate_action`; they carry **no `ActionSpec`** and are **not** `ActionClass` actions. `complete` is already a bare string (`loop.py:189`); `escalate` is compared as `ActionType.escalate.value`.
   All stay kernel-owned, or the kernel cannot run its own control terminal / memory write / scope-bounded read when driven by a non-audit pack.
3. **Domain action ids** — the audit *analyzers* (`build_graph`, `run_slither`, `run_mythril`, `run_auditor_skill`, `analyze_transactions`, `decompile_bytecode`, `write_poc`, `run_tests`, `deploy_test_contract`). These **move to the pack**. `read_file`/`search_code` are **not** here — they are generic scope-bounded reads in category 2a (D6), inherited by the pack, not domain analyzers.

`validate_action` therefore resolves each id **that reaches it** against **`KERNEL_GENERIC_ACTIONS ∪ pack.actions`** (resolvable ids only — `LOOP_TERMINALS` are handled earlier and are *not* in this union), fail-closed on a miss. Today `AUDIT_ACTIONS` is built `for t in ActionType` — so it *accidentally* includes `write_memory`/`request_human_confirmation`/`escalate` **and** `read_file`/`search_code`; after this feature the resolvable kernel ids (control/memory machinery + generic reads) come from `KERNEL_GENERIC_ACTIONS`, the terminals from `LOOP_TERMINALS`, and the pack declares only domain analyzers. This is decisions **D4** (the resolvable/terminal partition) and **D6** (reads are kernel-generic, not domain) — together they make B6 writable (it asserts on the kernel sets separately) and keep the kernel↔araratsec pair consistent.

## User Scenarios & Testing *(mandatory)*

The "users" are (a) the **kernel maintainer**, who must be able to state truthfully that the kernel is task-agnostic and have a test that proves it; (b) a **future second capability-pack author**, who needs the *domain* action taxonomy and privileged-status set to be pack-owned so their non-audit pack is expressible without editing the kernel — while still inheriting the kernel-generic control/memory ids for free; and (c) the **security reviewer**, who must be able to confirm that making the taxonomy open did not open a hole in the MI / confirmation guarantees (Principles I, II — NON-NEGOTIABLE).

### User Story 1 - The kernel's action taxonomy is open; the pack owns its *domain* action ids (Priority: P1)

`Action.action_type` becomes a free `str`. The kernel keeps the generic `ActionClass` taxonomy **and** a small kernel-generic action-id set (category 2 above) with kernel-provided `ActionSpec`s. The domain audit ids (category 3) leave the kernel entirely and are defined in the audit pack (paired feature 002); `TOOL_REGISTRY` and `_validate_params` move with them. `validate_action` resolves every id against `KERNEL_GENERIC_ACTIONS ∪ pack.actions` and derives confirmation/reversibility from the resolved `ActionSpec`.

**Why this priority**: This is the core Principle III fix and the largest single change. The pack-path in `validate_action` already keys by string and fail-closes on `pack.actions.get(key) is None` (`action.py:53–71`), so the pack side is a relocation, not a new abstraction. The one true blocker the pack docstring named — the closed `action_type: ActionType` annotation — is what this story removes.

**Independent Test**: With ONLY a kernel-only fixture pack present (`tests/fixtures/pack/FIXTURE_PACK`) declaring an invented **domain** id (e.g. `"do_thing"`) with an `ActionSpec(action_class=write_execute, is_reversible=False, validate_params=…)`, an `Action(action_type="do_thing", …)` round-trips through `validate_action` and correctly triggers the out-of-band confirmation gate (because `write_execute ⇒ confirm`), **and** a kernel-generic `write_memory` still resolves via `KERNEL_GENERIC_ACTIONS` — all with **no edit to any kernel domain enum**. Grep of `sr_agent/` finds zero domain audit ids.

**Acceptance Scenarios**:

1. **Given** `Action.action_type` typed as `str` and a fixture pack declaring `do_thing` as `write_execute`, **When** the model proposes `do_thing`, **Then** `validate_action` resolves its class from the pack's `ActionSpec` and the kernel derives "requires confirmation" from `action_class`, identically to how a `write_poc` was gated before.
2. **Given** the same fixture pack (which declares **no** control/memory ids), **When** the loop needs to `write_memory` or reach the `escalate`/`complete` terminals, **Then** those resolve from `KERNEL_GENERIC_ACTIONS` / the loop terminals — the kernel does not depend on the pack having declared them.
3. **Given** the kernel source after this feature, **When** grepped for `run_slither|run_mythril|run_auditor_skill|write_poc|run_tests|deploy_test_contract|analyze_transactions|decompile_bytecode|build_graph`, **Then** there are zero matches in `sr_agent/` (they live only in the audit pack).
4. **Given** an id in neither `KERNEL_GENERIC_ACTIONS` nor the active pack, **When** `validate_action` runs, **Then** it rejects (fail-closed) — an unknown id is never silently treated as `read_only`.

### User Story 2 - Domain privileged-statuses are pack-supplied, bound once at session start (Priority: P1)

The kernel's `REQUIRES_HUMAN_CONFIRMATION` frozenset stops hardcoding the audit statuses (`verified_safe`, `skip_analysis`, `audit_complete`). Instead, the **effective privileged-status set is composed by the kernel from the active pack's `privileged_statuses` once at session construction** and injected into the memory plane; `EpisodicMemory._enforce_status_rules` consults that bound set. The generic rule — "a status in the privileged set is writable only by `source_type == human_input`" — is unchanged; only the *membership* and its *binding path* change.

**This is not a symmetric mirror of US1, and the spec says so plainly.** The US1 pack-path already existed in `validate_action`; the US2 path does **not** exist yet. `_enforce_status_rules` is a `@staticmethod` (`episodic.py:210`) reading a module-level constant, and `EpisodicMemory.__init__(memory_root, secret_key)` (`episodic.py:47`) holds **no** reference to the pack. Consulting `pack.privileged_statuses` requires a **new coupling edge (pack → memory plane)** that must be built: the set is threaded into the memory instance at session construction and is thereafter immutable — no model turn can widen or narrow it. Calling this "a small membership swap" would understate it; it is a new, guarded binding path.

**Why this priority**: The status gate is one of the five MI-neutralizing mechanisms (MI-002 `skip_analysis`, MI-003 `verified_safe`). Relocating its source of truth without changing its guarantee is delicate and P1.

**Independent Test**: A kernel-only fixture pack declares a made-up privileged status (e.g. `"blessed"`); with the set bound at session start, a write of `status="blessed"` at `source_type=llm_inference` is rejected by `_enforce_status_rules`, while the same write at `human_input` is accepted — and the kernel `models/memory.py` names no audit status. A second assertion confirms the bound set cannot be mutated after construction.

**Acceptance Scenarios**:

1. **Given** the status set bound from `pack.privileged_statuses` at session start and a fixture pack declaring `blessed`, **When** a `llm_inference`-tier record tries to set `status="blessed"`, **Then** the write is rejected exactly as an `audit_complete` write was before.
2. **Given** the kernel source after this feature, **When** `sr_agent/models/memory.py` is read, **Then** `REQUIRES_HUMAN_CONFIRMATION` is empty (or removed) — no `verified_safe`/`skip_analysis`/`audit_complete`.
3. **Given** the audit pack unchanged in behavior, **When** the MI suite runs (MI-002, MI-003), **Then** both remain blocked (protected ASR unchanged).
4. **Given** a bound privileged set, **When** anything attempts to alter it mid-session (a model turn, a tool result), **Then** it cannot — the binding is immutable for the session's lifetime.

### User Story 3 - The guarantee is preserved and newly pinned; SC-005 is the primary proof (Priority: P1, NON-NEGOTIABLE)

Opening the taxonomy MUST NOT lower any guardrail (Constitution I, II). After US1+US2, the MI Attack Success Rate for protected runs stays 0, the hostile-pack tests (H1 skip-confirmation, H2 forge `human_input` tier, H3 opt out of containment) still pass, a **new hostile-pack test H4** pins the deliberately-narrowed status semantics (below), and a **new boundary test B6** pins the taxonomy cleanliness so the violation cannot silently return.

**The primary evidence of task-agnosticism is the positive fixture test (SC-005), not the grep (B6).** B6 is a grep-proxy — a Goodhart surface that only proves "these strings are absent." The real proof that the kernel works with *no task code present* is a kernel-only fixture pack driving a full validate→confirm cycle and a privileged-status rejection with the kernel's domain enums gone (SC-005). B6 is the auxiliary anti-regression latch that keeps the win from eroding.

**H4 (hostile / under-declaring pack).** Because privileged-status membership is now pack-supplied (US2), a hostile or buggy pack could declare an **empty or reduced** `privileged_statuses`. The intended, deliberate semantics — the kernel does **not** re-expand; a pack's status gate covers exactly what the pack declared — is a *narrowing of a near-non-negotiable guarantee* and MUST be an explicit, tested position, not an accident. H4 asserts: (a) an empty set means "this pack has no privileged statuses," not "gate disabled" (the gate still rejects an unknown-tier write of any status the pack *did* declare), and (b) a pack cannot use under-declaration to bypass a status the kernel would otherwise enforce — because post-US2 there is no kernel-default status to bypass; the concept is entirely pack-scoped. The narrowing is legitimate, but H4 makes it intentional and reviewed.

**Why this priority**: Constitution I is NON-NEGOTIABLE and Principle III says "That a pack cannot lower a guardrail is itself a security property and MUST be tested." This story is the safety net that makes US1/US2 shippable; it is P1 by definition.

**Independent Test**: `pytest tests/security tests/architecture` passes with the same protected-ASR (0) and differential (≥0.40) as before; SC-005's fixture-pack positive test passes; B6 fails on a deliberately reintroduced audit id and passes on the clean tree; H4 passes.

**Acceptance Scenarios**:

1. **Given** the full security suite, **When** run before and after this feature, **Then** `test_protection_asr_below_5pct`, `test_baseline_asr_above_40pct`, `test_differential_40pp`, and the three status/isolation blockers all pass unchanged.
2. **Given** the new boundary test B6, **When** the kernel's action registry is scanned, **Then** it asserts (a) `Action.action_type` is not a closed *domain* enum, (b) no domain audit id and no domain privileged-status is defined in `sr_agent/`, and (c) `KERNEL_GENERIC_ACTIONS == {write_memory, request_human_confirmation, read_file, search_code}` and `LOOP_TERMINALS == {escalate, complete}` (asserted separately); a reintroduced `write_poc` in the kernel makes B6 red.
3. **Given** `test_hostile_pack`, **When** a hostile pack tries H1/H2/H3 through the now-open taxonomy, **Then** all three are still refused; **and** H4 confirms an empty/reduced `privileged_statuses` behaves as the deliberately-narrowed semantics, not as a disabled gate.
4. **Given** the chat loop (`run_turn`) after the enum guards are removed (FR-004), **When** the model proposes a `next_action` absent from `KERNEL_GENERIC_ACTIONS ∪ pack.actions`, **Then** it is rejected and fed back as `[DATA]` (not forwarded past `loop.py:349`); **and** a `write_execute` domain action in chat mode gates for out-of-band confirmation identically to the batch path (SC-009) — the convenience surface opens no shortcut (Constitution II).

### User Story 4 - Residual audit vocabulary renamed to task-agnostic (Priority: P2)

The audit-flavored names that are domain *wording*, not domain *concepts*, are renamed to neutral terms, with a transitional backward-compat shim so the paired araratsec migration is not a hard breakage:

- `audit_root` → `scope_root` (the path-containment root threaded through `PackContext`, `orchestrator/loop.py`, `orchestrator/action.py`, `tools/readonly.py`, `tools/registry.py`). `PackContext` is a `@dataclass(frozen=True)` (`pack.py`), so a field `scope_root` coexisting with a read-only `audit_root` alias needs a `__getattr__`/shim, **not** a trivial property — the alias delegates to `scope_root`.
- `AuditResult` → `RunResult` (`orchestrator/loop.py:181,191`; the batch result). Note the chat path already returns a neutrally-named `TurnResult` — only `AuditResult` is renamed; no new type is invented.
- The default system prompt in `llm_core/claude_client.py` ("smart contract security auditor …") becomes a neutral kernel default; the audit wording is supplied by the pack's `reasoning_prompt` (which already overrides it).

**Why this priority**: Pure clarity — these names do not gate anything. `audit_root` is the widest single rename: **≈72 references in the araratsec pack core (audit_agent + tests + eval), ≈91 repo-wide** counting docs/config; the kernel side is ≈15. That volume is exactly why it needs the shim + lock-step handling (below), and why it is P2 (mechanical, cross-repo) rather than P1. The "mechanical/small" framing is deliberately dropped: the churn is real, protected by grep=0 success criteria, not by hand-waving.

**Independent Test**: Grep of `sr_agent/` for `audit_root`, `AuditResult`, and the audit system-prompt string returns zero *definitions* (only, at most, the deprecation shim); the kernel test suite passes against the new names.

**Acceptance Scenarios**:

1. **Given** `scope_root` as the `PackContext` field and a transitional `audit_root` shim, **When** downstream code still reads `ctx.audit_root`, **Then** it resolves to `scope_root` via `__getattr__` and emits a deprecation signal, until feature 002 migrates and PR-3 removes the shim.
2. **Given** `RunResult` in `orchestrator/loop.py`, **When** the kernel suite runs, **Then** it is green with no `AuditResult` symbol remaining except an optional alias, and `TurnResult` is untouched.

### User Story 5 - PoC context leaves the kernel `PackContext` (Priority: P2)

`PackContext.poc_dir` and `PackContext.poc_generator` are a Proof-of-Concept concept — squarely audit-domain — and are **removed** from the kernel `PackContext` (Resolved Decision D2), carried instead by pack-owned context. The kernel's narrow surface (`scope_root`, `sandbox`, `wrap_data`) then carries no PoC vocabulary. B3 (`tests/architecture/test_kernel_pack_boundary.py`) currently *knowingly tolerates* `poc_dir`/`poc_generator`; after this story B3's tolerance is removed and B6 forbids them.

**Why this priority**: P2 (was P3). The D2 decision that once made this a critical-path blocker is now **settled — removal** (see Resolved Decisions), so this is ordinary removal work, not a blocker; it stays P2 rather than dropping back to P3 because it is a genuine kernel-surface change (removing fields from a `frozen` dataclass, tightening B3→B6), not cosmetic. It sits behind US4 only because it touches fewer call sites (`poc_generator` has a single downstream reference, `dispatch.py:80`; `poc_dir` ≈34 in the pack core, ≈69 repo-wide).

**Independent Test**: `sr_agent/orchestrator/pack.py` `PackContext` names no `poc_*` field; the audit pack supplies PoC directory/generator through its own context object; the full araratsec suite still drives PoC generation.

**Acceptance Scenarios**:

1. **Given** the kernel `PackContext` after this story, **When** it is inspected, **Then** it has no `poc_dir`/`poc_generator` field and B6 asserts their absence.
2. **Given** the audit pack, **When** it generates a PoC, **Then** it sources the directory/generator from pack-owned state, and behavior is identical to before.

### Edge Cases

- **Kernel-generic ids are not domain ids (do not launder them into the pack)**: `escalate`, `complete`, `write_memory`, `request_human_confirmation` are Principle I/II machinery, and `read_file`/`search_code` are generic scope-bounded reads (D6). All stay kernel-owned (category 2). A second, non-audit pack MUST inherit them without declaring anything; requiring a pack to re-declare `escalate` (or `read_file`) would recreate the exact "kernel doesn't work without a domain pack" defect this feature removes.
- **Fail-closed must be relocated from the loop's enum coercion**: today the batch loop's `Action(action_type=ActionType(agent_action.next_action))` (`loop.py:202`, `:357`) *is* the entry fail-closed — an unknown string raises `ValueError` and is rejected; the chat loop additionally guards with `na not in ActionType._value2member_map_` (`loop.py:349`). After `action_type: str`, **both enum-based guards disappear**. The rejection MUST be guaranteed to live in `validate_action` (`KERNEL_GENERIC_ACTIONS ∪ pack.actions` miss → rejected) and the chat loop's `_value2member_map_` check MUST be rewritten to consult that same union. No code path may forward an unvalidated `next_action` past this point.
- **Unknown action id (fail-closed)**: with an open `str` action space, an id absent from `KERNEL_GENERIC_ACTIONS ∪ pack.actions` MUST be rejected, never defaulted to `read_only`. A permissive default would let a hostile or buggy pack smuggle a `write_execute` action past the confirmation gate by mislabeling it.
- **`run_auditor_skill` is dead downstream**: the audit pack has zero references to `run_auditor_skill` (no skill dispatch exists in araratsec). It is removed from the kernel and NOT resurrected in the pack unless feature 002 explicitly wants it — moving a dead id would launder dead code across the boundary.
- **HMAC safety of the `audit_root` rename**: memory records are HMAC-signed over `record.fields_for_hmac()` (MemoryRecord fields); `audit_root`/`scope_root` is a filesystem path parameter, not a signed record field (confirmed against `memory/hmac.py` + `memory/episodic.py:76`). The rename cannot invalidate any signature.
- **Privileged-status set becomes empty in the kernel**: `REQUIRES_HUMAN_CONFIRMATION` may become an empty frozenset whose membership is entirely pack-supplied and bound at session start. The gate MUST still function (an empty kernel set + a populated bound pack set behaves exactly as the old hardcoded set did for the audit pack).
- **A pack that declares no privileged statuses / no domain actions**: the kernel must not crash or fail-open on a minimal pack. Empty `privileged_statuses` means "no privileged statuses" (H4), not "gate disabled"; empty domain `actions` means every proposed *domain* id is unknown and fails closed, while kernel-generic ids still resolve.
- **Transitional window with both names live**: during PR-1→PR-2→PR-3, `audit_root` (shim) and `scope_root` (canonical) coexist and MUST refer to the same value, so no path reads a stale `audit_root` while another writes `scope_root`.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `Action.action_type` MUST be a free `str` (open string id), not a closed enum of domain ids. The kernel MUST NOT define any **domain** action id (`run_slither`, `run_mythril`, `run_auditor_skill`, `analyze_transactions`, `decompile_bytecode`, `build_graph`, `write_poc`, `run_tests`, `deploy_test_contract`).
- **FR-002**: The kernel MUST own (a) the generic `ActionClass` taxonomy; (b) **`KERNEL_GENERIC_ACTIONS` = `{write_memory, request_human_confirmation, read_file, search_code}`** — resolvable generic ids, each with a kernel-provided `ActionSpec`, that flow through `validate_action`: the control/memory machinery (`write_memory`, `request_human_confirmation`) and the generic scope-bounded reads (`read_file`, `search_code`) whose containment guard is a kernel safety primitive (D6); and (c) **`LOOP_TERMINALS` = `{escalate, complete}`** — loop signals intercepted before validation, carrying no `ActionSpec`. Both sets MUST be available to every pack without the pack declaring them. `KERNEL_GENERIC_ACTIONS` and `LOOP_TERMINALS` are separate named sets and MUST NOT be merged (they differ in whether they carry an `ActionSpec` and whether they reach `validate_action`).
- **FR-003**: `validate_action` MUST resolve each proposed id **that reaches it** against `KERNEL_GENERIC_ACTIONS ∪ pack.actions` and MUST reject (fail-closed) any id in neither. `LOOP_TERMINALS` are handled before validation and are NOT part of this union. `validate_action` MUST NOT assign a default `action_class` to an unknown id. The **sole authority for DOMAIN action metadata is `pack.actions`**; the sole authority for resolvable control/memory ids is `KERNEL_GENERIC_ACTIONS`.
- **FR-004**: The entry fail-closed currently provided by `ActionType(next_action)` coercion (`loop.py:202`, `:357`) and by the chat loop's `_value2member_map_` guard (`loop.py:349`) MUST be explicitly relocated: after `action_type: str`, unknown-id rejection is guaranteed by `validate_action`, and the chat loop's membership guard (`:349`) MUST be rewritten to consult `KERNEL_GENERIC_ACTIONS ∪ pack.actions`. No loop path may forward an unvalidated `next_action` downstream. The `LOOP_TERMINALS` (`escalate` at `loop.py:180`/`:341`, `complete` at `:189`/`:341`) continue to be intercepted before validation and MUST reference kernel-owned constants, not a removed enum. This requirement is verified by SC-009 (chat path), not only SC-005 (batch path).
- **FR-005**: The **domain** per-action parameter validation and the audit `TOOL_REGISTRY` MUST move to the audit pack (paired feature 002). The kernel MUST NOT import or reference audit tools or audit param-validators. **Per D6, the ladder is partitioned, not moved whole**: the `read_file`/`search_code` branches (`action.py:93–99`) stay kernel-side as the `validate_params` of the kernel-generic read `ActionSpec`s, and the path-containment helper (`_check_filepath`/`_contained`) stays a kernel safety primitive; only the domain-analyzer branches (`run_slither`, `run_mythril`, `analyze_transactions`, `write_poc`, `deploy_test_contract`) move to the pack, which imports the kernel containment helper rather than re-rolling its own path-traversal check. This partition is D6-mandated (those ids left the domain), not a gratuitous cleanup. The transitional `pack is None` legacy path in `validate_action` (`action.py`) MUST be removed once callers pass a pack (its enum-indexed `ACTION_CLASS_MAP[action.action_type]` breaks under `str` anyway).
- **FR-006**: The privileged-status membership consulted by `EpisodicMemory._enforce_status_rules` MUST be **composed by the kernel from the active pack's `privileged_statuses` at session construction and bound into the memory plane**, immutable for the session. No model turn or tool result may widen or narrow the bound set. The kernel MUST NOT hardcode `verified_safe`/`skip_analysis`/`audit_complete`.
- **FR-007**: The generic status-gate rule MUST be unchanged: a status in the bound privileged set is writable only by `source_type == human_input`; any lower tier is rejected. An empty bound set means "no privileged statuses" and the gate MUST still operate (fail-closed, never fail-open).
- **FR-008**: A new boundary test **B6** MUST assert that the kernel ships (a) no closed *domain* action enum on `Action.action_type`, (b) no domain audit id anywhere in `sr_agent/`, (c) no domain privileged-status in `sr_agent/`, and (d) that `KERNEL_GENERIC_ACTIONS` equals exactly `{write_memory, request_human_confirmation, read_file, search_code}` and `LOOP_TERMINALS` exactly `{escalate, complete}` (each asserted against its own set — `complete` is a loop signal, not a resolvable `ActionClass` action, so it MUST NOT appear in `KERNEL_GENERIC_ACTIONS`; `read_file`/`search_code` MUST appear there per D6, and MUST NOT be counted as domain ids by check (b)). B6 MUST fail if any domain id/status is reintroduced. B6 is the **auxiliary** guard; the **primary** proof is the SC-005 fixture-pack positive test.
- **FR-009**: A new hostile-pack test **H4** MUST assert the deliberately-narrowed status semantics: a pack declaring an empty/reduced `privileged_statuses` yields a gate that covers exactly the declared set (empty ⇒ no privileged statuses, not a disabled gate), and under-declaration cannot bypass a kernel-enforced status (there is none post-US2). H4 sits alongside H1/H2/H3 in `test_hostile_pack`.

## Governance Impact (constitution)

Two constitution touch-points, amended in araratsec (the constitution's source of truth) and mirrored here in the same change:

- **Principle II — this is a NARROWING and RELOCATION of a near-non-negotiable guarantee, not a wording tweak.** Today Principle II makes the kernel gate `{verified_safe, skip_analysis, audit_complete}` **unconditionally, independent of any pack**. After US2 the gate of these statuses depends on the pack having declared them; an under-declaring pack has a smaller gate (H4). This moves the *locus* of the guarantee from kernel-absolute to pack-declared-bound-at-session-start. The amendment MUST state this plainly — "the privileged-status set is pack-declared and bound by the kernel at session construction (audit pack: `verified_safe`, `skip_analysis`, `audit_complete`); the kernel enforces the gate over whatever the active pack declares" — and MUST NOT be filed as a mere PATCH clarification. Recommended: a MINOR bump (2.0.0 → 2.1.0), because the guarantee's shape changes even though the mechanism's intent is preserved. The security rationale (H4 makes the narrowing deliberate and tested) belongs in the amendment's Sync Impact Report.
- **Principle III** already *mandates* this outcome ("concrete action types … domain privileged-statuses … lives in a capability pack") — this feature brings the code into compliance, so III needs no textual change, but the amendment note should cite this feature as the one that closed the gap, and note the **kernel-generic exception** — the generic (non-domain) ids stay kernel-owned — so a future reader does not mistake it for a violation. The note MUST record that the exception carries **two different weights**: the control/memory machinery (`write_memory`, `request_human_confirmation`) is kernel-owned by *structural necessity* — the kernel is the only legitimate constructor (Principles I/II), so these could not live in a pack even in principle — whereas the scope-bounded reads (`read_file`, `search_code`, D6) are kernel-owned by *anti-duplication convenience* sitting on top of a kernel-owned safety primitive: the containment guard (`_contained`/`_check_filepath`) must be kernel-side, but the read *ids* could technically live in a pack importing that guard (the very pattern FR-005 prescribes for domain analyzers) and are kept generic only so every pack inherits reading for free. Recording this keeps a future reader from treating `read_file` as as-immovable as `write_memory`.

Propagation to both `.specify/memory/constitution.md` copies is part of the feature's Definition of Done.

## Resolved Decisions

- **D1 — domain action taxonomy = open string ids keyed to pack `ActionSpec` (variant b); the kernel keeps a generic id set.** The kernel already keys confirmation off `action_class`, and the pack already maps `str → ActionSpec`. Making `Action.action_type: str` and treating `KERNEL_GENERIC_ACTIONS ∪ pack.actions` as the resolution set is the minimal change that removes *domain* ids from the kernel while preserving its control/memory machinery. "Sole authority" language is scoped to **domain** ids = `pack.actions`; control/memory ids = kernel. Decided per user direction ("вариант (b)").
- **D2 — PoC context is REMOVED from the kernel `PackContext` (was `[NEEDS DECISION]`; resolved to removal).** Rationale: consistent with D1's "no domain vocabulary in the kernel," and the review flagged D2 as on the critical path blocking both paired features, so it is resolved now rather than at plan time. PoC directory/generator are carried by pack-owned context. The lighter `artifact_dir`/`artifact_generator` generalization is explicitly **rejected** — it would leave a generic-but-unused hook in the kernel with exactly one consumer. Revisit only if plan-phase churn analysis shows removal is disproportionate (single-consumer `poc_generator` at `dispatch.py:80` suggests it will not be).
- **D3 — transitional shim only for the cross-repo name (`audit_root`→`scope_root`).** `AuditResult`→`RunResult` needs no shim (kernel-internal, zero araratsec refs), and `TurnResult` is left as-is. Because `PackContext` is `frozen=True`, the `audit_root` shim is a `__getattr__` delegation, not a plain property.
- **D4 — the kernel-owned machinery/terminal ids split into two named sets, not one.** Answers the reviewers' shared Q1 and the round-2 follow-up. `KERNEL_GENERIC_ACTIONS` (the *resolvable* set — carry `ActionSpec`, reach `validate_action`) holds `write_memory, request_human_confirmation` (and, per D6, the generic reads); `LOOP_TERMINALS = {escalate, complete}` are loop *signals* intercepted before validation (`loop.py:180`/`:189`/`:341`), carrying no `ActionSpec`. `write_memory`/`request_human_confirmation`/`escalate`/`complete` are Principle I/II machinery the kernel's own loop constructs and branches on; requiring a pack to declare them would recreate the "kernel doesn't work without a domain pack" defect. `validate_action` consults `KERNEL_GENERIC_ACTIONS ∪ pack.actions` only (terminals excluded); B6 asserts on the two sets separately (`complete` is a signal, not a resolvable `ActionClass` action, so it MUST NOT be in `KERNEL_GENERIC_ACTIONS`). araratsec-002 Key Entities is corrected to drop these four from `AuditActionType` (and, per D6, `read_file`/`search_code` too).
- **D5 — the privileged-status set is bound at session construction, immutable by turn.** Answers the reviewers' Q2. The kernel composes the effective set from `pack.privileged_statuses` once when the session/memory plane is constructed and injects it into `EpisodicMemory`; no model turn can alter it. This is a new coupling edge (pack → memory) that US2 must build — explicitly *not* a free membership swap.
- **D6 — `read_file`/`search_code` are kernel-generic reads (id + tool stay kernel-side), not domain analyzers.** Answers the round-3 reviewers' shared finding: the earlier drafts left the read ids "domain" (araratsec `AuditActionType`) while assuming their tool-executors stayed kernel-side — one concept split across the boundary, and B6/SC-001 undecidable. Resolved by putting **both** the ids and their tools on the same (kernel) side, on three grounds: (a) both `read_file` and `search_code` are mechanically generic in the code — `readonly.py` is a path-contained text read and a substring search; the only domain flavor is `search_code`'s `.sol` default and "Solidity" wording, which are de-domained — `file_ext` becomes a **required** parameter (no default), so a missed call-site fails loud with a `TypeError` instead of silently widening the search scope (SC-004's characterization fixture snapshots the gated-action set / confirming statuses / PoC output, **not** `search_code` results, so a silent scope change would slip past it); (b) the path-containment guard (`_contained`/`_check_filepath`) is a **security primitive** the kernel must own (Principle I), and the pack's relocated domain ladder imports it rather than re-rolling path-traversal checks; (c) making reads generic follows D4's anti-duplication logic — a second, non-audit pack inherits file reading for free instead of re-declaring it. Consequences: `read_file`/`search_code` join `KERNEL_GENERIC_ACTIONS` (resolvable, kernel `ActionSpec`, `action_class=read_only`, reversible); their validator branches stay kernel-side (FR-005 partition); `SC-001`/`B6` keep them out of the domain-id checks; araratsec drops them from `AuditActionType` and inherits them. **Rejected alternative A — reads are fully pack-domain (id + tool both move):** it would force every future pack to re-declare and re-host file reading (the duplication D4 removes), push the containment primitive into pack code, and flip `SC-001` to forbid strings the kernel legitimately keeps. **Rejected alternative B — split ownership (id + `ActionSpec` in the pack, the containment helper stays kernel and is imported):** this is the *stronger* alternative, and the honest reason it loses is anti-duplication, **not** impossibility — it is mechanically feasible (it is exactly the pattern FR-005 prescribes for domain analyzers), but it re-introduces per-pack re-declaration of a universally-needed capability for no gain and would make `SC-001`/`B6` police an id that is not actually domain vocabulary. So the load-bearing reason reads stay kernel-generic is rationale (c) — a universally-needed capability whose duplication costs more than it saves — **not** the structural necessity that binds the control/memory machinery. Both alternatives are kept only as the fallback if a future read tool becomes genuinely domain-shaped (none is today).
